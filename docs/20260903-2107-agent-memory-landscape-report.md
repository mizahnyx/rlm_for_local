# Memory for AI Agents: Landscape Research Report (2025–2026)

**Purpose.** Context report comparing (A) a harness-internal, "behavior-as-content" memory design (RLM harness; markdown wiki vault; SQLite FTS5; quarantine→validate→promote gate; offline GEPA optimization against verifiable evals) against (B) Memanto (moorcheh-ai), a companion Memory-Agent service. Every major claim carries a URL. Marking: **[F]** = established fact verified against a paper/repo/docs this session; **[I]** = my inference/synthesis from cited sources.

---

## 1. The agent-memory landscape circa 2025–2026

| System | Mechanism | Forgetting | Curation |
|---|---|---|---|
| **Mem0** | Vector store + LLM "memory operations" | Policy-governed (model-decided DELETE) | Agentic at write time |
| **Zep / Graphiti** | Bi-temporal knowledge graph | Temporal edge *invalidation* (supersede, not delete) | Agentic at write time |
| **Letta (MemGPT)** | Self-edited in-context memory blocks + archival store | Context eviction + sleep-time consolidation | Agentic (agent edits own prompt/memory) |
| **A-MEM** | Zettelkasten note graph | None explicit; evolution rewrites attributes | Strongly agentic (memory evolution) |
| **Memobase** | Structured user profiles + event timelines | Configurable profile schema ("controllable memory") | Passive-ish; schema-constrained |
| **LangMem** | Extraction + consolidation over LangGraph Store | Consolidation merges/removes outdated memories | Agentic incl. *prompt rewriting* |
| **memtrace** | (ambiguous name — 3 projects, see below) | — | — |
| **Cognee** | KG + vector hybrid via ECL pipeline | Explicit `forget` API op | Pipeline-driven, not agent-judgment |
| **Memento** | Case-based reasoning (case bank of trajectories) | None described | Case retrieval + writing, no governance layer |

Details, with sources:

- **Mem0** **[F]**: extraction→consolidation pipeline; the LLM decides via tool-call among **ADD / UPDATE / DELETE / NOOP** per candidate fact — so deletion/contradiction handling is model-judgment per write, not a scheduled policy. Graph variant Mem0g. arXiv:2504.19413 (ECAI 2025): https://arxiv.org/abs/2504.19413 ; ops mechanism: https://arxiv.org/html/2504.19413v1 ; 2026 state-of-the-field blog (self-published, directional): https://mem0.ai/blog/state-of-ai-agent-memory-2026
- **Zep / Graphiti** **[F]**: temporal knowledge graph; new edges are LLM-compared against related existing edges and **contradicting edges are invalidated** (`t_invalid` set), i.e., facts are superseded with provenance, not deleted. Bi-temporal (valid time vs transaction time). arXiv:2501.13956: https://arxiv.org/abs/2501.13956 ; repo (MCP server, 20k+ stars): https://github.com/getzep/graphiti
- **Letta / MemGPT** **[F]**: LLM-as-OS virtual context management; the agent **self-edits its own prompt** via memory-block tools (core/recall/archival tiers). Sleep-time compute: a background agent rewrites shared memory blocks during idle time, reducing test-time compute ~5× on stateful tasks. Memory blocks: https://www.letta.com/blog/memory-blocks/ ; MemGPT paper arXiv:2310.08560; sleep-time compute arXiv:2504.13171: https://arxiv.org/abs/2504.13171 ; agent-memory overview: https://www.letta.com/blog/agent-memory/
- **Letta Context Repositories (Feb 2026)** **[F]** — directly validates approach (A)'s premise from inside the "memory service" school: Letta Code now stores the agent's memory as **files in the local filesystem, git-versioned with automatic commit messages**; agents manage their own memory programmatically (reorganizing hierarchy, editing frontmatter, progressive disclosure; "all context (skills, prompts, etc.) is git-tracked"). https://www.letta.com/blog/context-repositories/ ; https://www.letta.com/agent/ ; related: "Context Constitution" principles and Skill Learning (skills learned from experience) — https://www.letta.com/research/
- **A-MEM** **[F]**: Zettelkasten-style atomic notes; note construction, LLM-driven link generation, and **memory evolution** (new entries can trigger updates to attributes of historical notes). Gated? No — evolution is automatic. arXiv:2502.12110: https://arxiv.org/abs/2502.12110 ; https://github.com/agiresearch/A-mem
- **Memobase** **[F]**: profile-based long-term memory (structured user profiles + event timelines, per-user batch buffers, target <100ms recall). Apache-2.0, ~2.8k stars. **[I]** No peer-reviewed paper surfaced; cite the repo. https://github.com/memodb-io/memobase
- **LangMem** **[F]**: SDK for extraction, consolidation, background memory managers over LangGraph Store. Crucially for this comparison, LangMem explicitly treats **updated instructions in the agent's prompt as procedural memory** and ships prompt-update proposal algorithms (metaprompt / gradient / prompt_memory) — i.e., a memory product that *rewrites prompts* from conversation streams, with no eval-gate (unlike GEPA). https://github.com/langchain-ai/langmem ; launch post: https://www.langchain.com/blog/langmem-sdk-launch ; conceptual guide: https://langchain-ai.github.io/langmem/concepts/conceptual_guide/
- **memtrace** — **[F]** name collision, three distinct projects; flag which one you mean: (1) **Basekick-Labs/memtrace**: LLM-agnostic memory layer, *no embeddings/vector DB*, temporal structured records on a time-series DB, returns "LLM-ready markdown" session context for prompt injection; https://github.com/Basekick-Labs/memtrace (2) **zjunlp/MemTrace** (paper, arXiv:2605.28732): traces/errors memory-system failures as memory-evolution graphs + MemTraceBench benchmark; https://github.com/zjunlp/MemTrace ; https://huggingface.co/papers/2605.28732 (3) **memtrace (syncable-dev/motion2082)**: bi-temporal AST knowledge graph of codebases for coding agents, zero LLM calls; https://github.com/syncable-dev/memtrace-public . **[I]** In "agent memory" lists, (1) is the likely referent.
- **Cognee** **[F]**: open-source memory engine; ECL (Extract-Cognify-Load) pipeline builds KG+embedding memory; API exposes **`remember`, `recall`, `forget`, `improve`** — forgetting is an explicit first-class op. https://github.com/topoteretes/cognee
- **Memento (paper)** **[F]**: "Fine-tuning LLM Agents without Fine-tuning LLMs" — case-based reasoning formalized as Memory-Based MDP; case bank stores successful *and* failed trajectories; retrieval-augmented planning (optionally fine-tunes only a small planner). Top-1 GAIA validation 87.88% Pass@3, 79.40% test; CBR memory adds 4.7–9.6 pts on OOD tasks. arXiv:2508.16153: https://arxiv.org/abs/2508.16153 ; https://github.com/Memento-Teams/Memento
- **Policy-governed forgetting, specifically**:
  - **MemoryBank** **[F]**: Ebbinghaus forgetting-curve memory update mechanism (time elapsed × importance → forget/reinforce). arXiv:2305.10250: https://arxiv.org/abs/2305.10250
  - **Memory-R1** **[F]**: RL-trained (PPO/GRPO) Memory Manager that *learns* ADD/UPDATE/DELETE/NOOP from downstream answer correctness, with only 152 QA pairs. arXiv:2508.19828: https://arxiv.org/abs/2508.19828
  - **MemOS** **[F]**: memory OS with MemCube units carrying **lifecycle control, access policies, and version tracking** over three substrates (parametric / activation / plaintext-prompt memory). arXiv:2507.03724: https://arxiv.org/pdf/2507.03724 ; short version arXiv:2505.22101: https://arxiv.org/abs/2505.22101
  - **Memanto** **[F]**: policy-driven expiry with presets (conservative/balanced/aggressive), named first-match-wins rules, pinning, *reversible* expiry (memories recall labeled `[EXPIRED]` with the rule that retired them; `memory restore`). https://github.com/moorcheh-ai/memanto
  - **[I]** Synthesis: "forgetting" in 2025–26 systems comes in three grades — (i) retrieval decay (MemoryBank), (ii) contradiction invalidation (Zep, Mem0, Memory-R1, LangMem), (iii) explicit lifecycle policy (MemOS, Memanto, Cognee's `forget`). None of the mainstream systems *validates candidate writes against measurable outcomes before promotion* — that is the distinctive feature of your design (A)'s gate. **[I]**
- **Field surveys** **[F]**: "Rethinking Memory in AI" defines six atomic memory ops — Consolidation, Updating, Indexing, **Forgetting**, Retrieval, Compression (arXiv:2505.00675: https://arxiv.org/abs/2505.00675 ). "Memory in the Age of AI Agents" (Guibin Zhang et al., arXiv:2512.13564: https://arxiv.org/abs/2512.13564 ). "A Survey of Context Engineering for LLMs" (arXiv:2507.13334, 166pp: https://arxiv.org/abs/2507.13334 ).

## 2. Procedural memory / skill library — "behavior as content"

- **CoALA** **[F]** is the established taxonomy: a language agent has working memory + long-term **episodic** (experience), **semantic** (knowledge), and **procedural** memory — "procedural memory stores the production system itself: the set of rules that can be applied to working memory to determine the agent's behavior" (i.e., code/prompts/skills). Learning = internal actions that write to memory. arXiv:2309.02427: https://arxiv.org/abs/2309.02427 ; curated list: https://github.com/ysymyth/awesome-language-agents
- **Voyager** **[F]**: the canonical "skill library" — GPT-4 agent in Minecraft with automatic curriculum + an ever-growing library of **executable, interpretable, reusable code skills** stored and retrieved by embedding; iterative prompting for skill generation. arXiv:2305.16291: https://arxiv.org/abs/2305.16291 ; https://github.com/MineDojo/Voyager
- **Agent Workflow Memory (AWM)** **[F]**: induces reusable, abstracted **workflows** from past trajectories (offline or online) and injects them into agent memory to guide later tasks (WebArena, Mind2Web). arXiv:2409.07429: https://arxiv.org/abs/2409.07429 ; https://github.com/zorazrw/agent-workflow-memory
- **Agent Skill Induction (ASI), "Inducing Programmatic Skills for Agentic Tasks"** **[F]**: stores skills as **verifiable, composable executable programs** added to the action space — explicitly contrasting with AWM's non-executable text skills; +23.5% over static baseline and +11.3% over AWM on WebArena. This is the closest published precedent for *gate-checkable behavior content* (skills must pass verification before becoming callable). arXiv:2504.06821: https://arxiv.org/abs/2504.06821
- **SkillWeaver** **[F]**: web agents self-improve by discovering site skills, practicing them, and distilling them into **reusable APIs**; skill libraries transfer to weaker agents (OSU/CMU et al., Apr 2025). Index entry: https://github.com/OSU-NLP-Group/GUI-Agents-Paper-List
- **ExpeL** **[F]**: experiential learning = storing successful trajectories for retrieval **plus** extracting high-level **insights** that augment task instructions — insights are behavior text learned from experience. AAAI-24 (Oral). arXiv:2308.10144: https://arxiv.org/abs/2308.10144
- **Memp** **[F]**: procedural memory as a first-class optimization target — distills trajectories into fine-grained step instructions and script-like abstractions; studies Build/Retrieval/**Update** (continuous update, correction, deprecation of contents); memory transfers across stronger/weaker models; can also distill into weights. ACL 2026 per repo. arXiv:2508.06433: https://arxiv.org/abs/2508.06433 ; https://github.com/zjunlp/MemP
- **Letta Skill Learning / Context-Bench "Skill Use"** **[F]**: production framework shipping experience-learned skills loaded from a library, with an eval suite measuring skill discovery/loading. https://www.letta.com/research/
- **Self-evolving agent surveys** **[F]**: arXiv:2507.21046 "A Survey of Self-Evolving Agents: What, When, How, and Where…" (TMLR 01/2026) taxonomizes *what* evolves (model, memory, prompts, tools/skills, workflows) and *when* (intra- vs inter-test-time): https://arxiv.org/abs/2507.21046 ; arXiv:2508.07407 "A Comprehensive Survey of Self-Evolving AI Agents": https://arxiv.org/abs/2508.07407 ; living list: https://github.com/XMUDeepLIT/Awesome-Self-Evolving-Agents
- **Established term for "behaviour as content"?** **[I]** No single canonical term. The converging vocabulary across the literature is: **"procedural memory"** (CoALA — the umbrella), **"skill library"** (Voyager/ASI), **"workflows"** (AWM), **"playbook"** (ACE), **"context map"** (PEEK), **"context repositories"** (Letta), and most recently **"externalization / harness engineering"** — a 2026 unified review literally titled *"Externalization in LLM Agents: A Unified Review of Memory, Skills, Protocols and Harness Engineering"* (arXiv:2604.08224: https://arxiv.org/abs/2604.08224 ). Your phrase "behavior as content" maps most precisely onto **"externalized, versioned procedural memory"**; a commentator taxonomy "model / harness / artifact" (Shilong Liu blog — commentary, not peer-reviewed) makes the same three-way split: http://lsl.zone/blog/2026/a-taxonomy-of-self-evolving-agents

## 3. GEPA / reflective prompt evolution

- **GEPA paper** **[F]**: "GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning" (Agrawal, Tan, Soylu, …, Klein, Zaharia, **Khattab**; ICLR 2026 **Oral**). Genetic-Pareto optimizer: samples system-level trajectories (reasoning, tool calls, tool outputs), reflects in natural language to diagnose failures, proposes/tests prompt updates, and merges complementary lessons from the **Pareto frontier** of its own candidates. **Beats GRPO by 10% on average (up to 20%) with up to 35× fewer rollouts; beats MIPROv2 by >10% across two LLMs**; also useful as inference-time search for code optimization. Core position: natural language is a *richer learning medium than scalar-reward policy gradients*. arXiv:2507.19457: https://arxiv.org/abs/2507.19457
- **Standalone library & adoption** **[F]**: gepa-ai/gepa — "optimize prompts, code, and more with AI-powered Reflective Optimization"; adapters for DSPy and LangChain; used in Google ADK's `optimize` and (per repo) Microsoft's data curation judge prompts. https://github.com/gepa-ai/gepa
- **DSPy integration** **[F]**: `dspy.GEPA` — trainset supplies reflective updates, valset tracks Pareto scores, and docs instruct keeping a **final held-out test set separate** (i.e., the held-out regression protection pattern is native). https://dspy.ai/api/optimizers/GEPA/overview/ ; https://dspy.ai/getting-started/gepa-optimization/
- **dspy.RLM** **[F]**: DSPy module implementing Recursive Language Models (Zhang, Kraska, Khattab 2025) — context treated as external data examined via sandboxed Python REPL + recursive sub-LLM calls; swappable like ChainOfThought. https://dspy.ai/api/modules/RLM/ ; community writeup: https://www.cmpnd.ai/blog/rlms-in-dspy.html
- **PEEK** **[F]** (the DSPy-adjacent piece you asked about): *"PEEK: Context Map as an Orientation Cache for Long-Context LLM Agents"* (Zhuohan Gu, Qizheng Zhang, **Omar Khattab**, Samuel Madden; MIT CSAIL/Stanford; arXiv:2605.19932) — maintains a **small constant-sized "context map" living in the agent's prompt**, updated by a cache policy (Distiller extracts lessons from trajectories → Cartographer makes structured edits → Evictor enforces token budget). It **benchmarks against ACE** (a prompt/context-learning framework): +6.3–34.0% with 1.7–5.8× lower cost on long-context tasks, gains across Codex and other production agents. https://arxiv.org/abs/2605.19932 ; https://github.com/zhuohangu/peek ; community DSPy port: https://github.com/0xtotem/peek-dspy . **[I]** Relationship to DSPy: same senior-author cluster (Khattab) as GEPA/RLM; PEEK is model/agent-agnostic with an unofficial DSPy port; conceptually it is the "episodic→procedural cache" middle layer between a raw store and the prompt.
- **Offline prompt evolution vs online memory write/read as learning mechanisms** **[I — synthesis grounded in the above]**:
  - *Signal*: GEPA needs **verifiable eval outcomes** (metric + train/val split) per candidate; memory systems consume **unlabeled interaction streams** (LangMem background manager; Memanto "watches interaction streams"). Offline evolution pays an eval-compute cost but gets true outcome signal; online memory gets scale and immediacy but self-judged quality (ReasoningBank must *self-judge* success/failure before writing).
  - *Gate*: GEPA candidates survive Pareto selection against a val set (regression protection by construction); mainstream memory writes are ungated — quality drift is acknowledged even by vendors (Memanto's own caveat: cross-benchmark scores are "directional" and what should be measured is "estate quality over time: contradiction rate, staleness" — https://github.com/moorcheh-ai/memanto-evaluation ).
  - *Granularity*: GEPA rewrites system-level text; best-practice memory writes are incremental deltas (ACE's curator avoids monolithic rewrites to prevent "context collapse").
  - *Timing*: the self-evolving-agents survey's intra-test-time (within-task) vs inter-test-time (between tasks) axis is the clean way to place them: memory = typically intra/online; GEPA = inter/offline compile step. A hybrid (ACE) does both with the same playbook mechanism.
  - **[I]** No paper found that directly ablates GEPA-style offline prompt evolution against an episodic store as competing learning mechanisms; the nearest published comparisons are PEEK-vs-ACE (https://arxiv.org/abs/2605.19932 ) and Memp's build/retrieve/update strategy study (https://arxiv.org/abs/2508.06433 ).

## 4. "Harness school" vs "memory service school"

- **RLM (Zhang & Khattab, MIT CSAIL)** **[F]**: blog (Oct 2025) + paper "Recursive Language Models" (arXiv:2512.24601, with Tim Kraska). Position: **the prompt/context is an external environment** — a variable in a Python REPL that the LM programmatically peeks into, partitions, transforms, and recursively sub-queries; "RLMs defer these decisions entirely to the language model." Results: inputs >1 order of magnitude beyond context limits; even within-window, RLM(GPT-5-mini) beats GPT-5 on OOLONG-132k by ~34 pts (~114%) at similar cost, +49% at 263k; on BrowseComp-Plus 1K docs (6–11M tokens) RLM(GPT-5) holds 100% vs ReAct+BM25 ~80% at $0.99/query; median run cheaper than base model but heavy-tailed; post-trained **RLM-Qwen3-8B** +28% median, approaching vanilla GPT-5. https://alexzhang13.github.io/blog/2025/rlm ; https://arxiv.org/abs/2512.24601 ; library: https://github.com/alexzhang13/rlm
  - **[F]** What the RLM line says about where context/memory should live: *in the harness environment, manipulated by code* — not compressed into tokens and not (yet) in a persistent external service. RLM handles per-call context; **persistence across calls is not addressed** by the RLM paper. **[I]** The same group's PEEK answers that gap with a prompt-resident, policy-maintained cache — i.e., the Khattab-cluster trajectory is: REPL-as-context-store (RLM) → prompt-resident evolving map (PEEK) → eval-gated text evolution (GEPA). Your design (A) is the composition of exactly these three.
- **Memory-service school** **[F]**: Mem0/Zep/Memobase/Cognee/Memanto/MemOS externalize memory behind an API/SDK/MCP service with its own judgment layer. Memanto is the most explicit "second agent" framing: six behaviors — observe & extract, consolidate, reconcile (conflicts versioned and surfaced, not last-write-wins), **forget (policy-driven)**, **brief (session-start bootstrap)**, move knowledge (Open Knowledge Format; syncs `MEMORY.md` into projects; imports from Mem0/Letta/Supermemory). Local mode = Docker + Ollama, no outbound calls; per-agent namespaces; MCP/connect integrations for Claude Code, Codex, Cursor, etc. Retrieval = Moorcheh information-theoretic scoring (ITS); self-reported 89.8% LongMemEval / 87.1% LoCoMo (own eval repo, with an explicit caveat that cross-system benchmark numbers are "not comparable… directional"). White paper: *Memanto: Typed Semantic Memory with Information-Theoretic Retrieval for Long-Horizon Agents*, arXiv:2604.22085: https://arxiv.org/abs/2604.22085 ; repo: https://github.com/moorcheh-ai/memanto ; eval: https://github.com/moorcheh-ai/memanto-evaluation
- **Convergence evidence** **[F]**: the two schools are merging from both ends — Letta (service school) rebuilt memory as **git-versioned markdown/files the agent itself manages** (Context Repositories, MemFS, skills, Agent File `.af` open format: https://www.letta.com/blog/agent-file ), while Memanto (service school) adopts **portable Markdown as the working/exchange format**. **[I]** The remaining differences vs design (A): Memanto/Letta keep the *judgment* in a running service (or the live agent), the working store is a database/file tree without a promotion gate, and neither validates behavioral text against held-out eval suites before it ships. Design (A)'s distinctive stance — offline GEPA rewrites of prompt pages gated by verifiable evals + quarantine/promotion for self-proposed pages — has no mainstream equivalent I could find; the closest precedents are ASI's verified skill induction (execution-gated, arXiv:2504.06821), ACE's curator deltas (un-gated), and MemEvolve (see §5).
- **Prior art comparing the two schools head-on**: **[I]** none found as a controlled study. Closest artifacts: Memanto's own storage-vs-memory-agent comparison table (https://github.com/moorcheh-ai/memanto ); PEEK's related-work taxonomy of what agents preserve across calls (trajectory vs raw access vs strategies vs orientation knowledge, arXiv:2605.19932); the Externalization review (arXiv:2604.08224) which unifies memory, skills, protocols, and harness engineering in one frame.

## 5. Work that compares or combines prompt/skill evolution with episodic memory

- **ACE — Agentic Context Engineering** **[F]**: contexts as **evolving playbooks** maintained by Generator/Reflector/**Curator**; curator emits *delta entries* merged by non-LLM logic (prevents "context collapse" from monolithic rewrites). Runs **both offline (system prompts) and online (agent memory)**: +10.6% agents, +8.6% domain-specific, matches/others on AppWorld & Finance Agent. The single closest published system to design (A)'s "behavior as evolving content," minus the eval gate and git semantics. arXiv:2510.04618 (ICLR 2026): https://arxiv.org/abs/2510.04618
- **ReasoningBank + MaTTS** **[F]**: strategy-level memory distilled from self-judged successes *and* failures; Memory-aware Test-Time Scaling couples memory with parallel/sequential scaling so extra rollouts produce contrastive signals for better memory curation; consistently beats raw-trajectory and success-only memory on web/SWE benchmarks. arXiv:2509.25140: https://arxiv.org/abs/2509.25140
- **MemEvolve** **[F]**: *meta*-evolution — jointly evolves memory **content and the memory system's architecture** via tournament-style rounds with automatic candidate selection over task batches (EvolveLab harness; ICML'26 per repo). This is the closest thing to "GEPA for memory systems": architecture candidates are selected against measurable task performance. arXiv:2512.18746: https://arxiv.org/abs/2512.18746 ; https://github.com/bingreeky/MemEvolve
- **Memento** **[F]**: CBR case memory + a *separately fine-tuned small planner* — memory and learning combined, weights untouched for the main LLM. arXiv:2508.16153.
- **Memp** **[F]**: procedural memory that can be distilled into model weights (fine-tune from memory) or kept in-context; studies update/deprecation policies for procedural content. arXiv:2508.06433.
- **LangMem** **[F]**: memory→prompt direction in production SDK form (prompt-update proposals from conversations). https://www.langchain.com/blog/langmem-sdk-launch
- **Evo-Memory** **[F]**: benchmark for test-time learning with self-evolving memory in streaming task scenarios (ExpRAG baseline). arXiv:2511.20857: https://arxiv.org/abs/2511.20857 (per https://www.academia.edu/145691662/ )
- **Agent KB** **[F]**: cross-domain experience knowledge base shared across agents. arXiv:2507.06229 (cited across Memp/MemEvolve).
- **[I]** Gap statement: I found **no system that runs eval-gated offline prompt/skill evolution (GEPA-style) *and* an episodic memory store inside one agent with a controlled comparison of their contributions**. ACE comes nearest (one mechanism, two modes); MemEvolve evolves memory systems rather than behavior pages; Memp evolves procedural memory without a held-out regression gate. Design (A)'s specific combination — markdown-as-truth behavior pages + FTS5 index + quarantine→validate→promote + offline GEPA against verifiable suites — appears novel as a *composition*, though every individual ingredient has strong precedent (RLM, PEEK, ACE, ASI, Memp, Letta Context Repositories).

## Bottom line for A vs B **[I]**

- **(B) Memanto** is the polished end of the *external memory-service* school: an autonomous companion agent with policy-governed, reversible forgetting, conflict surfacing, session-start briefing, typed memory categories, local Docker+Ollama deployment, MCP integration — and, notably, Markdown as its portable working format and white-paper backing (arXiv:2604.22085). Its memory is **content about the world/users/tasks**, not the agent's own behavior.
- **(A)** sits in the *harness/procedural* school that the field is visibly converging toward (Letta Context Repositories, ACE, PEEK, MemOS "plaintext memory", the Externalization review). Its differentiators with precedent but no combined precedent: (1) behavior text is **git-versioned first-class content** (Letta does this for memory, not for eval-gated behavior evolution); (2) **two write paths** — self-proposed pages through a quarantine→validate→promote gate, and offline GEPA rewrites against held-out evals (mainstream memory has neither gate); (3) designed for **small local LLMs** (RLM/DSPy-lineage inference strategies, unlike Memanto's cloud-first retrieval engine).
- **Direct head-to-head research (A-style vs B-style) does not exist yet** as of this research pass; the nearest published benchmarks are PEEK-vs-ACE and MemEvolve's EvolveLab comparisons of memory-system variants.
